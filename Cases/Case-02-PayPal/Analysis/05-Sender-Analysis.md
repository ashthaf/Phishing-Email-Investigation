# Sender Analysis

## Objective

The objective of this phase is to analyze the sender-related headers to determine the apparent sender, the actual sending infrastructure, and identify any anomalies that may indicate spoofing or phishing activity.

---

# Sender (From Header)

The visible sender information was extracted from the email header.

Command used:

```bash
grep '^From:' ~/CyberLab/Cases/Case-02-paypal/Evidence/Headers/email-header.txt
```

Output:

```
From: Ihre einmalige Chance, jehd <service@stayfriends.de>
```

The display name attempts to attract the recipient's attention, while the visible email address belongs to the **stayfriends.de** domain.

# Return-Path Analysis

The Return-Path was extracted using the following command:

```bash
grep '^Return-Path:' ~/CyberLab/Cases/Case-02-paypal/Evidence/Headers/email-header.txt
```

Output:

```
Return-Path: return@messaggerocappuccino.it
```

The Return-Path differs from the visible sender address.

Visible sender domain:

```
stayfriends.de
```

Return-Path domain:

```
messaggerocappuccino.it
```

This indicates that the email was transmitted using mail infrastructure associated with **messaggerocappuccino.it** while presenting itself as originating from **stayfriends.de**.

Although different Return-Path domains can be legitimate, they should always be correlated with authentication and routing analysis.

# Message-ID Analysis

The Message-ID header was examined.

Observation:

```
Message-ID:
```

The header is present but does not contain a visible identifier.

Normally, Message-ID contains a unique value generated by the sending mail server. A missing or blank Message-ID is uncommon and should be treated as an observation during the investigation.

# Additional Sender Headers

The sender-related headers were manually reviewed.

Observed results:

| Header | Status |
|---------|--------|
| From | Present |
| Return-Path | Present |
| Reply-To | Not Present |
| Sender | Not Present |

No Reply-To header was identified.

This means replies would default to the address specified in the **From** header.

No Sender header was identified.

According to RFC 5322, the Sender header is optional and is generally included only when the actual sender differs from the author listed in the From header.

# WHOIS Analysis – Visible Sender Domain

The visible sender domain (**stayfriends.de**) was investigated using WHOIS.

The domain is registered and publicly resolvable.

Domain registration alone does not confirm legitimacy because attackers may abuse compromised or legitimately registered domains.

# Findings

The sender analysis identified several important observations:

- Visible sender address:
  ```
  service@stayfriends.de
  ```

- Display name:
  ```
  Ihre einmalige Chance, jehd
  ```

- Return-Path:
  ```
  return@messaggerocappuccino.it
  ```

- Return-Path domain differs from the visible sender domain.

- Reply-To header not present.

- Sender header not present.

- Message-ID header is present but contains no visible identifier.

- Both domains are registered according to WHOIS records.

---

# Conclusion

The sender analysis identified a discrepancy between the visible sender domain and the Return-Path domain.

While this difference alone does not confirm phishing, it represents an important indicator that must be correlated with routing analysis, authentication analysis, content analysis, and URL analysis.

At this stage, the sender information alone is insufficient to determine legitimacy, but it provides valuable forensic evidence for the overall investigation.
